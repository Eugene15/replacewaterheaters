# Adapting the florist kit

## What is florist-specific

- bouquet, florist, recipient and occasion vocabulary;
- delivery and handoff questions;
- flower/product imagery rules;
- local florist versus marketplace competitor taxonomy;
- florist confirmation and payment facts;
- Product, Offer and service-area schema decisions;
- flower-intent prompt families;
- current approved examples and owner memory.

## Adaptation sequence

1. Define the target product, customer and conversion.
2. Replace `project-context.json` fields marked `ADAPT_REQUIRED`.
3. Replace all canonical facts and prohibited claims.
4. Define target buyer jobs and query families.
5. Replace competitor categories and local-intent interpretation.
6. Register the target project's real UI component inventory.
7. Add its brand/design constitution.
8. Clear florist-specific owner memory and approved examples.
9. Rewrite GEO prompts and canonical brand facts.
10. Run the config validator.
11. Pilot one market and two or three clusters end-to-end.

Keep the stage graph, evidence lineage, independent reviews, memory precedence, immutable approval and release guard unless deliberately redesigned.
